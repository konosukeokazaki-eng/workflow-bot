1. このツールについて

Workflow Bot は Google Chat 上で稼働する申請・承認／定型文送信ツールです。従来メールやチャットで口頭でやり取りしていた申請フローを、スペース内のボタン1つで開始でき、結果はすべてスプレッドシートに自動保存されます。

できること

  • Chat スペースに「申請する」ボタンを配置し、ダイアログで入力させる
  • 申請内容を承認者宛てにカードで届け、承認/却下などを記録する
  • 複数の入力項目（テキスト・プルダウン・チェックボックス・日付・数量付きチェック）を自由に組み合わせる
  • 申請承認→別のワークフロー起動の連動（最大3階層）
  • 結果を外部スプレッドシートにも同時書き込み

2種類のワークフロー

種類用途例
申請・承認誰かの承認が必要な手続き。ステータス（承認待ち→承認／却下）が記録される有給申請、経費精算、備品購入
定型文送信承認不要で内容を記録・共有したい連絡日報、来客記録、業務連絡

2. 登場人物と権限

役割できること
オーナー (owner)全ワークフローの作成/編集/削除、管理者の追加/削除、スプレッドシートへの直接アクセス
エディタ (editor)全ワークフローの作成/編集。削除は自分が作成したもの、または共同編集者に指定されたもののみ
メンバー (member)自分が作成したワークフロー、または共同編集者に指定されたワークフローのみ閲覧/編集可能
申請者Chat 上でボタンを押して申請を出す。管理画面にはアクセスできない
承認者届いた申請を承認/却下する。各ワークフロー編集画面でメール単位に指定

3. 申請者向け：申請の出し方

方法1：ボタンから申請する

  1. 指定された Google Chat のスペースを開きます
  2. 「申請する」などのボタンカードを探してクリック
  3. ダイアログで必要項目を入力（「*」付きは必須）
  4. 「送信」ボタンを押す

方法2：/apply コマンドから

  1. Chat メッセージ欄で /apply と入力
  2. そのスペースで利用可能なワークフロー一覧が出るので、目的のものを選ぶ
  3. 以降はボタン操作と同じ

送信後の流れ

  • 申請・承認型：送信先スペース（未設定なら実行スペース）に承認カードが届き、承認者が処理すると結果がカードに反映されます
  • 定型文送信型：送信先スペースに投稿されて完了
必須項目が未入力のまま送信した場合、ダイアログは閉じずに警告が表示されるので、埋め直して再送してください。

4. 承認者向け：承認・却下の仕方

  1. 送信先スペース（未設定時は申請元の実行スペース）に「🔔 新しい申請」カードが届きます
  2. カード内の申請内容を確認
  3. 下部のボタン（「承認」「却下」等、ワークフロー定義によって異なる）を押す
  4. ブラウザで結果画面が開き、処理が完了
  5. Chat に戻るとカードのステータス表示が更新されています
承認用リンクには有効期限（発行から30日）があります。期限切れの場合は申請者に再申請を依頼してください。
シークレット/プライベートブラウザで開くと認証されず「権限がありません」になります。通常ブラウザで会社の Google アカウントがプライマリにログインされている状態で開いてください。
承認者が1名も登録されていないワークフローは、管理者であっても承認できません。必ず最低1名の承認者を登録してください。

5. 管理者向け：ワークフローの作成

管理画面にアクセスし、左サイドバー「新規」を押すとフォームが開きます。①基本情報 / ②フォーム項目 / ③承認・通知（または通知設定）の3つのセクションに分かれています。

①基本情報

  • ワークフロー名：スプレッドシートのシート名にもなります。80文字以内、/ \ ? * [ ] : は使用不可
  • 種類：「申請・承認」か「定型文送信」
  • 実行スペース（必須・複数選択可）：申請ボタンを設置する Chat スペース
  • 送信先スペース（任意）：承認カード/定型文の投稿先。空欄なら実行スペースにそのまま返信されるため、スペースごとに通知先を分けたい場合は空欄推奨
  • 説明文（任意）：申請ダイアログのヘッダに表示

②フォーム項目

「＋項目を追加」で入力項目を追加します。

種類用途・備考
テキスト（1行）氏名、金額、短い理由
テキスト（複数行）詳細な説明、備考
プルダウン選択肢をカンマ区切りで入力。1つだけ選ばせる
チェックボックス選択肢をカンマ区切り。複数選択可
数量付きチェック各選択肢に数量を入力させる（例：「ペン×3, ノート×1」）。数量入力は半角数字直接入力か、カンマ区切りのプルダウンから選択可。数量「0」は未選択扱いで記録に残りません
日付単一日付のピッカー

「必須」にチェックを入れると、未入力では送信できません。

③承認・通知（申請・承認型）

  • 承認者（必須）：1名以上必須。「メンバーから選択」で送信先スペースの参加者一覧から選べる。メール直接入力も可
  • @メンション通知：「メンバーから選択」で選んだ承認者には承認カード投稿時に Chat の @メンション通知が飛びます（メール直接入力だけでは通知は飛びません）
  • メンション文言：デフォルトは「承認をお願いします」。変数 {申請者}、{ワークフロー} が使えます
  • アクションボタン：次節で詳述
  • 外部スプレッドシート連携：別のシートにも同時書き込みする場合に URL を指定

アクションボタンの2種類

タイプ挙動設定項目
ステータスを設定
（通常ボタン）		 押下でシートの「ステータス」列を指定値に更新し、カードも更新する ボタン名、ステータス値、色、スレッド返信ON/OFF、返信メッセージ
他のワークフローを起動
（連動ボタン）		 押下で別のワークフローの申請ダイアログを即座に開く。連動先が送信されると、設定したステータス値で親カードも更新される 連動先ワークフロー（事前に作成要）、スレッド継承ON/OFF、連動後に親に設定するステータス値（任意）
「スレッド返信」ON の場合、ステータス確定後に承認カードのスレッド内へ自動返信を投稿します。{申請者}、{ステータス} を使えます。

保存

右下「保存」で確定。入力漏れがあるセクションのチップに赤バッジが付き、該当セクションへ自動遷移します。保存した時点では Chat にはまだ反映されません。次節の「配置」を行ってください。

6. Chat への配置

  1. 左リストから配置したいワークフローを選ぶ
  2. 右上「配置」ボタンを押す
  3. 登録された実行スペース全てに申請ボタンカードが自動投稿される

再配置

設定変更後にもう一度「配置」を押すと、古いカードは削除され新しいカードに置き換わります。ボタン名や項目を変えたら必ず再配置してください。

Bot のスペース参加

初めてのスペースへの配置時は Workflow Bot が自動で参加します。参加できなかった場合は保存時に警告が出ますので、スペース管理者に手動招待を依頼してください。

有効/無効の切り替え

サイドバーの各ワークフローのトグルで一時無効化できます。無効にすると /apply 一覧に出なくなり、既存配置のボタンを押しても動作しなくなります。

7. 高度な設定

連動ボタン（他のワークフローを起動）

承認カードから次のワークフローを起動して多段フローを組めます。

  • 連動先ワークフロー：先に連動先ワークフローを「新規作成→配置」まで済ませておきます。連動元の編集画面で「他のワークフローを起動」タイプのボタンを追加し、連動先を選択
  • スレッド継承 ON：起動した連動先ワークフローのカード（承認カード or 定型文）は、親ワークフローの承認カードと同じスレッドに投稿されます。1件の依頼として履歴を追いやすい
  • スレッド継承 OFF：連動先ワークフロー自身の送信先スペースに新規メッセージとして投稿されます。独立した件として扱いたい場合に使用
  • 連動後に親に設定するステータス値（任意）：連動先ワークフローが実際に送信された時点で、親の承認カードのステータスをこの値に更新します。連動ボタンを押しただけでは更新されず、連動先が送信されて初めて反映されます。空欄なら更新しません。既に通常ボタンで承認/却下済みの行は上書きしません
  • 連鎖上限：3階層まで（親→子→孫）。それ以上の連動は拒否されます（無限ループ防止）
運用例：「購入申請」で承認後、「発注依頼」ワークフローを連動起動（スレッド継承ON）→ 同じスレッドで発注依頼が流れ、全履歴が1件のスレッドにまとまる。

外部スプレッドシート連携

各部署が既に使っているスプレッドシートに申請データを同時書き込みできます。

  1. 外部スプレッドシートを開き、右上「共有」から Workflow Bot のサービスアカウントメールを編集権限で追加
  2. 管理画面のワークフロー編集で「外部スプレッドシート」欄に URL を入力
  3. 保存時に接続確認が走り、問題があれば警告が出ます

外部シートにはワークフロー名と同じシートが自動作成され、以降のすべての申請が両方に書き込まれます。

8. データとスプレッドシート

すべてのデータはマスタースプレッドシートに保存されます。「管理データ」ボタン（オーナーのみ表示）から直接開けます。

シート名内容
_設定ワークフロー一覧と設定
_項目設定各ワークフローの入力項目（fieldId/dataCol 管理含む）
_ボタン設定各ワークフローのアクションボタン（タイプ/連動設定含む）
_管理者管理画面にアクセス可能なユーザーと権限（owner/editor/member）
_監査ログ誰がいつ何をしたかの履歴（自動記録）
（ワークフロー名）そのワークフローの申請データ本体
_ で始まるシステム用シートは直接編集しないでください。特に _項目設定 の fieldId / dataCol を変更するとデータ列がズレます。確認のみに使用してください。

データシートの構造

各ワークフローのデータシートは以下の列構造です。

タイムスタンプ | 送信者 | 送信者メール | <入力項目1> | <入力項目2> | ... | ステータス | メッセージ名
  • 「ステータス」列は申請・承認型のみ
  • 「メッセージ名」は Chat カードの内部 ID（カード更新・スレッド返信・連動起動で使用）
  • 項目を削除してもデータ列は残り（過去データ保全のため）、新しい項目は末尾に追加されます

9. 管理者の追加・権限

  1. 左下「管理者」ボタン（オーナーのみ）を開く
  2. メールアドレスを入力し、権限（owner/editor/member）を選択して追加
  3. 「保存」で確定
自分自身を削除/降格して保存すると、以降この管理画面にアクセスできなくなります。信頼できる別の owner を必ず残してから編集してください。

権限の違い（詳細）

  • owner：すべての操作が可能。管理者の追加/削除、マスタースプレッドシート直接アクセス、全ワークフローの削除
  • editor：全ワークフローの作成/編集・配置。削除は自分が作成したものと共同編集者指定されたもののみ
  • member：自分が作成したか、共同編集者に指定されたワークフローのみ閲覧/編集/削除

10. アーカイブと復元

削除したワークフローは直ちに消えず、30日間アーカイブに保管されます。

  • 左下「アーカイブ」ボタンから一覧表示
  • 「復元」で元の状態に戻せる
  • 30日経過すると自動完全削除
  • 「完全削除」ボタンで即時削除も可能（取り消し不可）
同名のワークフローを再作成したい場合、同名のアーカイブがあると「既に存在します」エラーになります。アーカイブ内の該当を「完全削除」してから再作成してください。

11. 困ったときは

管理画面にログインできない

  1. URL が script.google.com/a/macros/cmind-co.jp/s/… の形式か（ドメイン付き URL でないと権限判定が働きません）
  2. ブラウザのプライマリアカウントが会社の Google アカウントか
  3. _管理者 シートに自分のメールが登録されているか（既存管理者に依頼）
  4. 管理者追加直後は最大5分の反映ラグ

申請したのに Chat にカードが出ない

送信先スペースに Bot が未参加の可能性大。該当スペースのメンバー一覧で「Workflow Bot」の有無を確認し、無ければ手動追加。その後、管理画面で該当ワークフローの「保存」を押し直すと再チェックされます。

承認ボタンを押しても「権限がありません」

  1. 「承認者」欄のメールアドレスが正しいか（全角/半角、余分な空白）
  2. プライマリアカウントが会社の Google アカウントか
  3. シークレット/プライベートブラウザで開いていないか

承認ボタンを押しても「無効なリクエスト」

承認リンクは発行から30日で失効します。申請者に再申請を依頼してください。

連動ボタンを押しても次のワークフローが起動しない

  1. 連動先ワークフローが「有効」になっているか
  2. 連動が3階層を超えていないか
  3. 連動ボタンの「連動後に親に設定するステータス値」を指定している場合、連動先が送信されるまで親のステータスは更新されません（ボタンを押した時点では未更新）

スレッド継承 ON なのに新規メッセージになる

親ワークフローの承認カードの「メッセージ名」列が記録されていない可能性があります。該当行をスプレッドシートで確認してください。空の場合、親カード投稿時にエラーが発生しています。管理者にログの確認を依頼してください。

データシートの列を誤って削除した

「タイムスタンプ」「送信者」「送信者メール」「ステータス」「メッセージ名」の各システム列は、次回申請/承認処理時に自動的に末尾に復旧されます。ただし過去データとの列対応はズレるため、可能な限り手動編集は避けてください。

それでも解決しない場合

以下を控えて管理者（konosuke.okazaki@cmind-co.jp）にご連絡ください。

  • 発生日時
  • 操作内容（可能ならスクリーンショット）
  • ワークフロー名
  • 表示されたエラーメッセージ全文
